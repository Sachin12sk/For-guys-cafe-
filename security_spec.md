# FOUR GUYS CAFE — Firestore Security Specification

## 1. Data Invariants
1. **Identity & Ownership**: A document at `/customers/{userId}` can ONLY be read, created, updated, or deleted by the authenticated user whose `request.auth.uid == userId` (or a verified admin).
2. **SMS Phone Integrity**: A customer profile's `phoneNumber` MUST strictly equal `request.auth.token.phone_number` (the SMS-verified E.164 phone number from Firebase Phone Authentication). Users cannot claim or spoof another customer's mobile number.
3. **Immutable Audit Fields**: `uid`, `phoneNumber`, and `createdAt` cannot be altered after creation. `createdAt` on create and `updatedAt` on create/update must equal `request.time`.
4. **Master Gate for Subcollections & Cloud Orders**: Both `/customers/{userId}/orders/{orderId}` and `/orders/{orderId}` MUST verify parent `/customers/{uid}` exists (`exists(...)`) and has matching `uid == request.auth.uid`. Customers cannot tamper with past order totals (`allow update` denied to customers; `/orders/{orderId}` allows only verified admins to toggle `isFlagged`/`flagReason`).
5. **PII & Order Isolation**: No unauthenticated or cross-user reads or list queries are ever allowed on `/customers`, `/customers/{userId}/orders`, `/orders`, or `/customerProfileLookup`. Verified Cafe Admin reads `/orders` and `/customerProfiles` using a dedicated admin Firebase Auth session (`adminAuth`). `/customerProfiles/{profileId}` requires a high-entropy `custprof_<16-64 chars>` capability ID (`allow list: if isAdmin();`), preventing phone enumeration or cross-customer PII leaks. `/customerProfileLookup/{lookupId}` (`cpl_<64 hex>`) stores only `{ lookupId, profileId, updatedAt }` with zero raw PII so reinstall recovery cannot leak or hijack customer identities.
6. **Admin Isolation**: `/admins/{adminId}` is strictly read-only (`allow write: if false`) from client SDKs so no user can self-assign admin privileges.
7. **Location Consent & Address Validation**: `ward`, `area`, `wardArea`, and `deliveryAddress` are bounded string fields; `geoLocationUrl` accepts ONLY empty string `''` (no GPS shared) or an explicit `https://maps.google.com/?q=lat,lng` link captured strictly after explicit user click/consent.
8. **Live Catalog Admin-Only Write & Credential Exclusion**: `/store/catalog` is publicly readable for live menu/prices/cafe open-closed status across Website & Android App, writable ONLY by verified Admin (`isAdmin()`), and explicitly rejects `adminId`, `adminMobile`, or `adminPin`.
9. **Live Order Status, Payment Verification & Idempotent Deduplication**: Zero-OTP guest orders in `/orders/{orderId}` are strictly write-once (`orderStatus == 'pending'`, `paymentStatus in ['unpaid', 'pending_verification']`, no `paymentVerifiedAt`, `createdAt == request.time`), cannot be read back or listed by other customers, and ONLY verified Admin may transition `orderStatus` (`pending | confirmed | preparing | ready | delivered | completed | cancelled`) and `paymentStatus` (`unpaid | pending_verification | paid`) with `statusUpdatedAt == request.time` / `paymentVerifiedAt == request.time`. Deterministic document IDs block duplicate retries.
10. **Reviews, Vibe Snaps & Referral Isolation**: Public reviews (`/reviews`) and Vibe Wall snaps (`/vibeSnaps`) require authenticated creation, strict schema/image-URL bounds, are immutable (`allow update: if false`), and can only be deleted by Admin. Referral entries (`/referrals`) are strictly private to the owning customer or Admin.

## 2. "Dirty Dozen" Adversarial Payloads (Must All Return PERMISSION_DENIED)
1. **Unauthenticated Customer Read**: Anonymous/unauthenticated `get /customers/uid_123` or `list /customerProfiles`.
2. **Cross-User PII Snooping**: Authenticated user `uid_attacker` calling `get /customers/uid_victim` or `get /orders/ORD-VICTIM`.
3. **Blanket Customer/Order List Scraping**: Guest or non-admin calling `list /customers`, `list /customerProfiles`, or `list /orders`.
4. **Weak / Guessable Profile Capability ID**: Guest attempting `create /customerProfiles/short_id` or phone-number-keyed `/customerProfiles/9876543210`.
5. **UID Spoofing on Create**: Authenticated user `uid_1` attempting `create /customers/uid_1` or `create /orders/ORD-1` with `uid`/`customerUid: "uid_victim"`.
6. **Shadow / Ghost Field Injection**: Guest or user sending `{ ..., isAdmin: true, verified: true }` in `create` or `update` on `/customerProfiles/*`, `/customers/*`, or `/orders/*`.
7. **Timestamp Forgery**: Sending a backdated `createdAt` or `updatedAt` instead of `request.time`.
8. **Immutable Field Tampering**: Attempting `update /customers/uid_1` to change `phoneNumber`, `uid`, or `createdAt`, or changing `profileId` / `createdAt` on `/customerProfiles/*`.
9. **Resource Exhaustion / Size Poisoning**: Sending a 5KB string in `customerName` or `itemsSummary`, or a 1KB junk document ID.
10. **Orphaned / Negative Order Creation**: Guest sending invalid mobile/name, negative `totalAmount: -500`, or pre-forged `orderStatus: 'completed'` on `create /orders/ORD-1`.
11. **Order Tampering**: Non-admin attempting `update /customers/uid_1/orders/ord_1` or `update /orders/ORD-1` to alter `totalAmount`, `itemsSummary`, or `orderStatus` (also prevents immutable snapshot mutation when profile updates).
12. **Privilege Escalation**: Authenticated user `uid_attacker` attempting `create /admins/uid_attacker` or using an unverified email token claiming admin email.
